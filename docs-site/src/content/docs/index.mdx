## One library, two kinds of item

Let's sort the shelves before you start searching them. SuperLibrary keeps two kinds of item, and
both carry the outcome that tells you whether the work earned another look.

**Artifacts.** Files and folders, uploaded by people or linked by agents through AgentPod. Versioned,
secret-scanned on the way in, and shown in a sandboxed viewer on a separate origin.

**Work records.** SuperPipeline work history, one record per card, kept current by signed push events.

**Outcomes.** Every item says how it turned out: approved, completed, in-progress, superseded, rejected,
failed or abandoned. Search ranks good work first and never hides the rest.

**Four ways in.** The web app, the `suli` command line, an MCP server with three read-only tools, and an
HTTP API.

That gives us one memory with four doors instead of four places to forget the same thing. Start with
[what it is](/what-it-is/), then [install `suli`](/install/) when you are ready to use the terminal.

SuperLibrary runs on Cloudflare Workers and signs people in through the SuperJackfruit account
service.
